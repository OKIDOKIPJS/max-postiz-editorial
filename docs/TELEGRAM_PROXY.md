# Явный локальный proxy для Telegram

Telegram Bot API может использовать уже запущенный локальный HTTP proxy, если
прямое соединение недоступно. Настройка относится только к HTTP-клиенту этого
адаптера; системные настройки, VPN, маршрутизация Windows и proxy-сервис не
изменяются.

В локальных `options` адресата задайте имя отдельной переменной:

```json
{"proxy_env": "TELEGRAM_PROXY_URL"}
```

В игнорируемом `.env.local` тестовой копии:

```dotenv
TELEGRAM_PROXY_URL=http://127.0.0.1:10809
```

Это пример существующего локального HTTP listener, а не команда его запуска.
Допускаются только HTTP, явный порт и loopback `127.0.0.1`, `localhost`, `[::1]`.
Учётные данные, path кроме `/`, query/fragment и внешние адреса отклоняются.
SOCKS в этом контракте не включён и дополнительные зависимости не устанавливаются.

Без `options.proxy_env` соединение остаётся прямым, даже если в окружении есть
`TELEGRAM_PROXY_URL`, `HTTP_PROXY`, `HTTPS_PROXY` или `ALL_PROXY`. Имена обычных
ambient proxy-переменных нельзя подставить вместо отдельной переменной.
Если явно настроенная переменная отсутствует/невалидна, автоматического возврата
к прямому соединению нет. Токен берётся только из отдельного `token_env`.

Клиент сохраняет `trust_env=false`, проверку TLS-сертификата и запрет redirects.
Proxy не разрешает иной API origin и не меняет защиту durable claims/unknown.
Injected MockTransport остаётся fixture и никогда не переключается на proxy.
Это необходимо, потому что HTTPX proxy mounts иначе могут переопределить
injected transport. Механизм proxy и `trust_env` описаны в официальной
[документации HTTPX](https://www.python-httpx.org/advanced/proxies/) и
[описании переменных окружения](https://www.python-httpx.org/environment_variables/).

Смена переменной окружения применяется при создании нового адаптера. Для
долгоживущего worker нужен согласованный перезапуск тестовой копии; рабочий
сервер MAX этим не затрагивается.

Успешный GET корня `api.telegram.org`, создание бота/канала и inspect — разные
проверки доступа. Ни одна из них не подтверждает доставку сообщения. До новой
разрешённой отправки с точным snapshot публикация не заявляется; read-only
inspect также сохраняет `verification=access_only` и `live_verified=false`.
