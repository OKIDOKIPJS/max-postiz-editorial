Подготовленный нами черновик закрыт через «Выйти без сохранения», Send не нажимался | Вход владельца в отдельный профиль копии, живая отправка и чтение результата |

В отключённой от сети одноразовой копии реального редактора прошли production `_fill_editor`, `_check_editor`, `_final_editor` для одного и нескольких абзацев с обычным переносом строки | Живая публикация и чтение нового поста; передача изображения и сохранение его SHA на площадке |

Все адресаты копии остаются выключены и на паузе. Внешних текстовых постов
не создавали; `TargetApproval`/`Dispatch` для предложенных живых тестов не
создавались. Согласование предложенного текста и времени ожидается отдельно.
Новые маршруты не наследуют автоматическое согласование политики MAX.

Проверка Пикабу использовала собственную тестовую авторизацию: страницы
persistent context оставались на `about:blank`, а его storage state читался
только в память и передавался одноразовому ephemeral context. Файлы cookies/
storage не создавались, их содержимое не выводилось. Все non-GET/HEAD, XHR/fetch и WebSocket
блокировались до загрузки, а перед первым вводом сеть отключалась необратимо.
На успешных финальных проверках: внешних изменений, загрузок и кликов Publish —
ноль, оба context закрыты штатно, cookies/storage на диск не экспортировались.
Это доказательство реального редактора offline, не доказательство доставки.

## Ограничения формата и эксплуатации

- Для Пикабу неоднозначный завершающий перевод строки отклоняется до изменения
  редактора; строка не обрезается и не подменяется. Обычные внутренние абзацы
  и одиночный перенос строки проверены на реальном редакторе offline.
- `media_contract_verified=false` у обоих новых браузерных маршрутов блокирует
  изображения до отдельного разрешённого теста. Преобразование байтов площадкой
  не снимает проверку SHA автоматически. Видео и альбомы не добавлялись.
- Telegram принимает до 4096 UTF-16 единиц полного текста; подпись к фото —
  до 1024. `auto` может создать фото и отдельное сообщение с полным текстом:
  каждый внешний шаг имеет собственный durable claim, продолжение неизвестного
  результата и автоматический повтор запрещены.
- Личный VK публикует обычный заголовок. Дополнительная отправка в Story
  выключается перед публикацией и проверяется повторно; чтение стены не
  объявляется независимым доказательством отсутствия Story во всём аккаунте.
- CAPTCHA, изменение интерфейса, потеря lease/approval, `sending`/`unknown`
  останавливают операцию. Reconcile читает существующий результат и не отправляет
  повторно. Старые fixture/API receipt/исторические флаги различаются в панели.
- Собственный Docker stack Postiz не запускался: Docker daemon недоступен.
  Панель/BFF проверяются локальными контрактами и TypeScript; это не живая
  приёмка развёрнутого Postiz. Старые эксплуатационные записи README/CHANGELOG
  сохранены как датированная история, а не новая проверка VM.

не менялись, различия были только в трёх документах. Шесть пропусков: четыре
проверки symbolic link без соответствующих Windows-привилегий и две проверки

TestClient. Ruff для `src`, `tests`, `scripts` и `pip check` прошли.

Ранее общие прогоны выявляли WinError 5 при локальном атомарном сохранении
benchmark-отчётов; они не выдаются за успешный QA. Добавлен ограниченный повтор
только Windows rename без повторения LT/модели/HTTP. После этого весь frozen
прогон выше завершился успешно; отдельные 90 regression-проверок сохранения
и прежних quality/input-history gates тоже прошли.

Полный прогон включает Telegram HTTP fixtures, browser regression/protocol
tests, exact approval/unknown/lease и собственную PostgreSQL test DB.
74 отдельные интеграционные проверки маршрутизации, API, доказательств и
конкурентного durable dispatch также прошли. Реальная offline-проверка редактора
Пикабу дополняет их; эти результаты не заменяют живую публикацию.

После отдельной UI-правки access-only inspect полный Node/UI набор со strict
semantic TypeScript завершился: **67 passed, 0 failed, 0 skipped**, 3,61 с.

доставка по-прежнему явно не проверена. Fixture имеет приоритетную локальную

## Где запускать

Настройка, команды создания авторского черновика, preflight, точного approval,
паузы и read-only сверки описаны в [FOUR_PLATFORM_ROUTES.md](FOUR_PLATFORM_ROUTES.md).
`scripts/start-four-platform.ps1` по умолчанию показывает только состояние.
Он не включает адресатов, не снимает паузу и не запускает отправитель.

Секреты бота, DSN и параметры реальных адресатов сохранены только в игнорируемых
файлах подготовленной копии. Профили браузеров принадлежат ей. Source archive,
sdist и wheel не являются резервной копией авторизации и не содержат runtime,
Docker volumes, installers, cookies либо `.env.local`.
